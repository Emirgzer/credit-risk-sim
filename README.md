# credit-risk-sim

Synthetic borrower data with a known default process, plus probability-of-default (PD) models evaluated the way credit risk teams do it.

Real loan data is hard to share, so credit models are often tested on synthetic data first. Because this generator draws defaults from a logistic model with coefficients I chose, the "true" PD of every borrower is known. That makes it possible to check how close a trained model gets to the best achievable result.

## What it does

1. **Generate** 50,000 borrowers (in about 3 seconds) with income, employment, credit history, utilisation, late payments and loan terms. Defaults are calibrated to a target rate (8% by default).
2. **Inject edge cases** into a share of rows: zero income, missing credit history, extreme debt-to-income, maximum loan size, and 18-year-olds with no credit file.
3. **Validate** the data before training: schema, value ranges, unexpected missing values, duplicate IDs and the default rate.
4. **Train and compare** two models: logistic regression (the explainable scorecard standard) and histogram gradient boosting.
5. **Evaluate** with ROC AUC, Gini, KS, Brier score and a predicted-vs-observed calibration table by decile, and map PDs to a points-based credit score (600 points at 50:1 odds, 20 points to double the odds).

## Quick start

```bash
pip install -r requirements.txt
python -m creditsim generate --n 50000      # data/borrowers.csv
python -m creditsim validate                # data quality checks
python -m creditsim train                   # metrics + reports/
pytest -q                                   # 14 tests
```

## Results (50,000 borrowers, 25% test split)

| Model | ROC AUC | Gini | KS | Brier |
|---|---|---|---|---|
| True PD (ceiling) | 0.825 | 0.650 | 0.498 | 0.0557 |
| Logistic regression | 0.825 | 0.649 | 0.500 | 0.0558 |
| Gradient boosting | 0.813 | 0.627 | 0.487 | 0.0566 |

Logistic regression matches the ceiling because the data was generated by a logistic process: the simpler model has the right shape, and the more flexible model pays for its extra variance. On real data with non-linear effects the result could flip, which is why both are compared.

Calibration is close across deciles (for example, the riskiest decile predicts 40.3% and observes 41.1%).

## Design choices

- **No leakage:** `interest_rate` and `monthly_payment` are excluded from the features, because the rate is priced from risk and would leak the answer.
- **Missing values are informative:** numeric features are median-imputed with missing-value indicator columns, so "no credit history" can carry its own signal.
- **Reproducible:** every run is seeded; the same seed always produces identical data.
- **Fail early:** `train` refuses to run on data that fails validation.

## Project layout

```
creditsim/
  generator.py   synthetic borrowers, default process, edge cases
  validate.py    data quality checks
```
